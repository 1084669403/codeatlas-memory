# Engineering requirements

1. Stable error codes and deterministic JSON.
2. Repository-relative POSIX paths in metadata.
3. Fingerprints must include referenced files, symbols, gate definitions, and plan revision.
4. Stale evidence must remain visible until revalidated.
5. Skill output must be bounded and must not become a second source of truth.

# Architecture decisions

Add `plan_memory.py` as the derived-memory core between plan workflow and indexing. `service.py` orchestrates update/doctor reports; CLI and Skill are adapters only. Mermaid is rendered from structured tables, never parsed from hand-written diagrams.

# Compatibility and migration

Existing 1a-1c plans remain readable. Missing fingerprints are treated as unknown, not automatically stale. Existing doctor behavior remains available if no plans directory exists.
