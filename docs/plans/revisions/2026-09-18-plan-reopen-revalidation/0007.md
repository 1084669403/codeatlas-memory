# Goal

Add an explicit, auditable workflow for reopening a stale batch in a done plan
so gate evidence can be refreshed without silently trusting the old `done`
status or bypassing canonical validation.

# Non-goals

Do not rewrite stale evidence, bypass human reapproval for semantic plan edits,
enable automatic rollback, or allow `update` to mutate plan state.

# Testing strategy

smoke test. Finish with full regression because the plan status machine is a
cross-cutting contract.

# Execution notes

Implement one batch at a time. `mark_batch_stale` remains the only way to mark
evidence stale. `reopen_batch` may only transition a stale batch in a done plan
to blocked, preserve `stale_evidence`, and record a durable audit event. Then
`plan batch start` creates a new batch-start revision so only fresh gate
evidence can complete the batch.

# Engineering requirements

Keep transition logic in `plan_workflow.py`, use stable error codes, and keep
CLI handling adapter-only. Preserve authoritative Markdown history through
revision snapshots and events. Require a non-empty reason. Do not remove old
evidence or invent passing outcomes.
