Make the context VM safe for multiple sessions and plans by isolating working
sets while preserving global compatibility.

  enrichment.
- Do not change page token accounting or stale/gone semantics.
- Do not break default global context behavior or existing indexed databases.

# Validation

Run the tests named in the testing contract.

# Testing strategy

Create projects with two scopes loading the same page. Each scope must retain
independent status and eviction decisions, while a database created before this
change upgrades in place as global scope. Same-scope writers must use a short
lease and explicitly release it.

# Execution notes

Implement one validated batch at a time.

# Engineering requirements

- Treat no scope as the existing global working set.
- Apply scope precedence deterministically: batch > plan > session > global.
- Keep scope keys deterministic and bounded.
- Use SQLite transactions for scope writes.
- Use short-lived leases with owner, expiry, and explicit release.
- Never evict a page owned by another scope unless explicitly forced.
- Preserve stale/gone reporting per scope.
- Keep SQLite migration in-place and additive where practical.
