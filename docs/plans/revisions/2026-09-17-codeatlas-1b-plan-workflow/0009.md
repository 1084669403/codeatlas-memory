# Engineering requirements

1. Keep workflow logic independent from Typer, Rich, SQLite, and MCP.
2. Use stable machine-readable error codes.
3. Preserve malformed plans; never silently rewrite them.
4. Use repo-relative POSIX paths in outputs and metadata.
5. Make every revision snapshot and audit event deterministic except planned timestamps.

# Architecture decisions

Use a pure `plan_workflow.py` layer over the 1a parser. Durable revision snapshots belong beside the Markdown plans because they are part of the auditable workflow. A small JSON projection under `.codeatlas/plans/` is enough for 1b; SQLite is deferred until query and doctor needs justify a migration.
