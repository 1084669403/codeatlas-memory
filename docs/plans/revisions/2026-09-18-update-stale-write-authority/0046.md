# Goal

Make update-time stale revalidation explicit and safe: when recorded batch
inputs no longer match current code, `update` can mark the affected passed batch
stale through the canonical plan writer, but only when plan-state writing is
allowed. A stale batch can then be explicitly restarted for fresh validation,
closing the evidence-refresh loop.

# Non-goals

Do not rewrite gate evidence, change plan goals or scope, reopen a `done` plan
automatically, bypass semantic reapproval, or make indexing depend on plan
mutation.

# Execution notes

Implement one validated batch at a time. `update` must call
`plan_workflow.mark_batch_stale`, never edit plan Markdown directly. Skip and
report malformed or conflicted plans. Preserve old evidence and stale evidence.
Restarting a stale batch is explicit, advances `batch_started_revision`, and
requires fresh gate evidence.

# Engineering requirements

Keep update as the orchestrator, put reusable behavior in the core, and keep
CLI/MCP output as adapters. The canonical writer increments revision, records
snapshot/event/projection, and rejects stale writes. Report-only mode must be
safe when write authority is disabled. Stale restart remains canonical and does
not trust old evidence.
