# Execution notes

# Engineering requirements

1. Every evidence item has `evidence_id`, `kind`, `ref`, `reason`, `confidence`, `stale`, and `source_path`.
2. Deterministic tie-break order: exact match, shorter qualified name, repo path, stable evidence ID.
3. JSON includes `tokens`, `truncated`, and explicit `reasons`.
4. Missing index produces a bootstrap hint with a stable error code.
5. Keep MCP output free of raw stdout interference.

# Architecture decisions

Add `plan_context.py` as the retrieval core between the derived index and adapters. The first slice combines exact/FTS symbol matches, stale checks, call-graph neighbours, and convention files. File-dependency traversal can be added later without changing the response contract.
