# Execution notes

1. Keep Markdown as the authoritative source.
2. Store durable snapshots under `docs/plans/revisions/<plan-id>/`.
3. Store only rebuildable projections under `.codeatlas/plans/`.
4. Reject stale or self-contradictory revision metadata.
5. Stop after each batch and run its validation.

# Engineering requirements

1. Keep workflow logic independent from Typer, Rich, SQLite, and MCP.
2. Use stable machine-readable error codes.
3. Preserve malformed plans; never silently rewrite them.
4. Use repo-relative POSIX paths in outputs and metadata.
5. Make every revision snapshot and audit event deterministic except planned timestamps.

# Architecture decisions

Use a pure `plan_workflow.py` layer over the 1a parser. Durable revision snapshots belong beside the Markdown plans because they are part of the auditable workflow. A small JSON projection under `.codeatlas/plans/` is enough for 1b; SQLite is deferred until query and doctor needs justify a migration.

# Security and privacy

Treat plan content as data. Do not execute plan text or accept conversational approval as durable approval. Keep files inside the configured project root.

# Compatibility and migration

Existing 1a plans remain readable. Plans with `content_hash: pending` are accepted for lint compatibility but cannot be approved until they are re-created or refreshed with a canonical hash.
